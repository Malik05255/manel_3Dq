# Saudi Floorplan Benchmark

هذا المجلد هو خط القياس الرسمي لقارئ المخططات في **منزلي HAI**. الهدف منه منع تبديل القارئ أو إعلان تحسن بناءً على الانطباع. أي تعديل على القراءة يجب أن يمر على نفس الحالات المرجعية ويخرج أرقامًا قابلة للمقارنة.

لا يحتوي المستودع العام افتراضيًا على مخططات خاصة. يجب أن تكون كل حالة مملوكة أو مرخصة، منزوعة الهوية، ولها مرجع يدوي موثوق.

## القارئ المقاس حاليًا

الـBenchmark مقفول على محرك الإنتاج:

`cubicasa-unet-resnet34-v3`

ويتم التنفيذ من خلال `backend/app/parser_v3.py`. إذا تغيّر `model_used` بدون تعديل سياسة القياس صراحة، يفشل الاختبار بدل أن يقارن محركًا مختلفًا وكأنه نفس الإصدار.

## ما يتم قياسه

`backend/scripts/run_saudi_benchmark.py` يقيس لكل مخطط:

- `wall_f1`: تطابق الجدران ضمن سماحية هندسية.
- `room_f1`: تطابق الغرف ومواقعها ونوع الغرفة عندما يكون النوع موسومًا.
- `opening_f1`: الأبواب والنوافذ حسب النوع والموقع والعرض التقريبي.
- `dimension_accuracy`: الأبعاد الصحيحة ضمن 5% أو 12 سم، أيهما أكبر.
- `overall`: متوسط موزون حسب `quality-gate.json`.

## بوابة الدقة

السياسة الحالية في `quality-gate.json`:

- الجدران: 95% فأعلى.
- الغرف: 95% فأعلى.
- الأبواب والنوافذ: 90% فأعلى.
- الأبعاد: 95% فأعلى.
- النتيجة الكلية: 93% فأعلى.

لا يتم تفعيل أي ادعاء عن الدقة الواقعية قبل وجود **30 حالة test حقيقية على الأقل** واجتياز جميع الحدود. الوصول إلى 100 حالة يبقى هدف النضج الأول للـBenchmark السعودي، ثم 300 ثم 500.

وجود 0–29 حالة مفيد للتطوير واكتشاف الأخطاء، لكنه لا يسمح بقول إن القارئ وصل إلى نسبة دقة إنتاجية.

## شروط كل حالة

كل صف في `manifest.jsonl` يجب أن يحتوي على:

- `license`: حق استخدام أو موافقة واضحة.
- `deidentified=true`: إزالة الأسماء وأرقام القطع والهواتف وأي بيانات غير لازمة.
- `city` و`region` و`project_type`.
- تقسيم ثابت `train` أو `validation` أو `test` لمنع تسرب القياس.
- `asset`: ملف المخطط الحقيقي.
- `reference`: وسم يدوي مرجعي للجدران والغرف والفتحات والأبعاد.
- `floors`: عدد الأدوار.

مثال:

```json
{"id":"riyadh-001","city":"الرياض","region":"central","project_type":"villa_two","source":"licensed-private","license":"owner-consent-2026-001","deidentified":true,"split":"test","asset":"assets/riyadh-001.png","reference":"labels/riyadh-001.json","floors":2}
```

يمكن إبقاء الملفات الأصلية في مخزن خاص. عند تشغيل القياس خارج المستودع استخدم:

- `SAUDI_BENCHMARK_ASSET_ROOT` لمسار ملفات المخططات.
- `SAUDI_BENCHMARK_REFERENCE_ROOT` لمسار ملفات الوسم المرجعي.

## شكل المرجع

المرجع JSON يستخدم نفس الإحداثيات النسبية 0–100 التي يعيدها القارئ:

```json
{
  "walls": [
    {"start":{"x":10,"y":10},"end":{"x":90,"y":10}}
  ],
  "rooms": [
    {"x":12,"y":12,"width":35,"height":30,"type":"bedroom"}
  ],
  "openings": [
    {"x":50,"y":10,"width":4,"type":"door"}
  ],
  "metric": {
    "dimensions": [
      {"value_m":4.0}
    ]
  }
}
```

## التقارير

كل تشغيل ينتج:

- `benchmark-contract-report.json`: سلامة الحقوق وإزالة الهوية والتقسيمات.
- `benchmark-execution-report.json`: نتائج كل حالة، متوسط test، حالة البوابة، وهل يسمح بإعلان الدقة أم لا.

الحالات الأساسية للبوابة:

- `NO_DATA`: لا توجد بيانات حقيقية؛ لا توجد مطالبة بالدقة.
- `INSUFFICIENT_TEST_CASES`: توجد بيانات لكن أقل من 30 حالة test.
- `PASS`: العدد كافٍ وكل مؤشرات الدقة تجاوزت الحدود.
- `FAIL`: القارئ تراجع عن حد واحد أو أكثر، ويجب إصلاحه قبل الاعتماد.
